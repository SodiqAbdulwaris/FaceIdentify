## What changed

Owner decision 2026-10-09 (the two things revision `0010` does were approved together):

- **A deleted artifact may have no location.** The `artifacts.location` CHECK demanded an
  `external_path` for every referenced artifact, so permanently deleting a Source that referenced the
  user's file left its path on the tombstone. The check now also accepts `state = 'DELETED'`, and
  deletion clears the path (`PermanentSourceDeletion._begin`). The user's file is still never touched.
  Managed artifacts keep only their id-derived storage key; the name, type, hash and size of every
  owned artifact are already cleared when the deletion finishes.
- **A history entry that the deletion happened.** `SOURCE_PERMANENTLY_DELETED` joins the Evidence kinds
  (identity model section 41). The finalizing transaction writes one, with the Source id and the ids of
  the identities that lost something, and nothing else: no face, crop, vector, name, path, run or
  subject. `PermanentSourceDeletion` gains a `new_id` argument for it.
- **Libraries already holding a deleted original.** The upgrade also clears the path and the file-describing
  columns of every referenced artifact an earlier revision had marked `DELETED` (a finished deletion or one
  in progress), and, if it cleared any, sets the durable `wal_truncation_owed` marker so startup recovery
  truncates the log that still holds the old values. Deletions finished before `0010` get no history entry.
- Migration `backend/alembic/versions/0010_deleted_artifacts_and_source_deleted_evidence.py` recreates
  `evidence` and `artifacts` in batch mode (like `0008`/`0009`); the model and the schema tests are
  updated, and the persistence spec's Evidence kind list gets a dated note.

## Tests

- `tests/integration/test_migration_0010.py` (8, two for the legacy rows: cleared and the truncation owed; and nothing owed when nothing was cleared): a populated 0009 database keeps every row and accepts
  the new rules (and still refuses a missing location on a live artifact, an unknown kind and a dangling
  reference); downgrade on an empty library; downgrade refused for a populated one unless forced; a
  forced downgrade stopped by data the old rules refuse, for both tables, leaving the database
  unchanged; the revision printed as SQL.
- `tests/integration/test_permanent_source_delete.py` (37, +3): the path of a referenced original is
  cleared and appears nowhere in the artifact rows; the history entry carries only affected identity ids
  and names no face, file or person; retained Evidence still keeps every earlier entry unchanged.
- Four mutations (path kept, empty payload, wrong kind, filename kept); the last survived because the
  finalizing transaction already clears the filename, so the duplicate was removed.
